# M17, the platform design gate — the consolidated triage

**Target:** `docs/designs/m17-design-gate.md` (revision 1)
**Round:** 1
**Date:** 2026-11-04
**Reports:** `m17-design-gate-review-1.md` (readiness),
`m17-design-gate-zoomout-1.md` (zoom-out), `m17-design-gate-critic-1.md` (critic),
`m17-design-gate-security-review-1.md` (security)

**The comprehension lens did not run.** It exceeded the round's time budget and was stopped,
so it is recorded here as **not run** rather than as a lens that found nothing — the same
distinction the first design's round 1 drew. Four of the five lenses reported; the round's
findings below are the four that came back.

**77 findings from four lenses: 17 blockers, 39 majors, 12 nits, 2 criticals, 4 highs.** Thirty-three of them
are the same defect found by more than one lens, and the six that mattered most were not wording:
the gate could not open, could not close, could not deliver its findings, could be handed a plan
that omitted it, could be walked around through the operator's own dispatch route, and lost its
artifacts on a restart.

Every finding below carries one disposition. Nothing was left undecided.

## The six that changed the design

| finding | lenses | what was wrong | what changed |
|---|---|---|---|
| The chain stalls on the operator | zoom-out, critic | only the operator writes `DONE`, so the review was never dispatched | a design task and a review task now reach `DONE` on their own verdict; every other task keeps the operator's approval |
| The findings go nowhere | critic | they rode the implement task's next packet, and a blocked task is never dispatched | the gate releases the implementation when the review clears, and the packet it is then given carries the design and the findings |
| The gate is a property of the plan, and the plan is an input | security | `validatePlan` checked ids, dangling prerequisites and cycles only | `validatePlan` refuses a plan whose story has no gated implementation, and whose review has no design |
| The operator's route ignores the dependency | security | `dispatchNow` applied lease, drift and egress, and no dependency check | `dispatchNow` refuses a task whose prerequisite is not done, and the board refuses to unblock a task the gate is holding |
| The artifacts vanish on a restart | critic | the load path read `kind = ArtifactHandoff` only | the load path reads handoffs, designs and reviews |
| The change list was short five files and its counts did not follow | readiness, zoom-out | the list omitted the count mirrors, the validator, the schema CREATE and the conformance file | the change list is generated by the four phases, and every count is derived from it |

## The isolation probe

One marker was planted in each standing file before the round: `.claude/CLAUDE.md`, `AGENTS.md`,
`GEMINI.md` and the three files in `.claude/rules/`. The four reviews returned no marker, and
`grep -rn "EGM-MARKER-" docs/designs/reviews/` returns nothing.

The **positive control** was run with the exclusion deliberately disabled: a control read the
standing files and returned three of the six markers verbatim. The probe can therefore detect a
leak, which is the only thing that makes the clean result mean anything. Every planted marker was
removed afterwards, and `deploy/check-workspace.sh` confirms none is left.

## What the round cost

The design did not survive its first review, and it should not have: revision 1's gate could not
open. Revision 2 is the result of applying the table above, and it is the version that was
implemented.
