Integrations

Traffic

The Traffic page in the back office shows the calls GAOS made to other platforms — the QA tool, the AI manager, GitHub, the WhatsApp gateway, Brain Town and TaskMgr — and the calls made to GAOS: every machine-API call, and every request that reached GAOS without passing through the edge. It keeps at most 48 hours, each kind only its newest records, and every direct caller since the dashboard started. It is for periodic monitoring; it blocks nobody (D-107, BR-66).

What is recorded

Each call is one record in a short trace that lives in the deployment’s own traffic store. It is not an event: nothing in GAOS reads it to decide anything, and it may be dropped, evicted or trimmed.

DirectionA record holdsNever
OutboundThe platform, the time, the method, the status (or the error class — timeout, canceled, dns, refused, reset, tls, other), the duration, the sizes, the host, and the path relative to the platform’s configured base with identifiers replaced: {base} for the configured part, {n} and {id} for numbers and identifiers, {ref} after a branch, {path} after a file path. A TaskMgr call adds its gRPC code and outcome.A header, a body, a query string, a fragment, a cookie, a token, a password, an error’s text, a configured base path, a branch name or a file path.
InboundFor an API call: the route pattern (never the path), the method, the status, the duration, the sizes, the source address, whether it came through the edge, the authenticated client’s name and the product id. For any other direct request: only the time, the method, the status, the duration, the route class, the source and direct.

ArcadeDB, GAOS’s own database, is not recorded; its health is on /api/healthz. Recording never delays or fails a call: a record that cannot be stored is counted, and the page shows the count.

Edge and direct

Every request carries the hop that delivered it to GAOS’s proxy. When that hop is the edge, the request came through the public site and is edge; otherwise it is direct — a machine on the tunnel, or a process on the VM, calling GAOS’s port. A request that passed through no proxy at all is direct too.

RequestKept in
Direct, an API call by an authenticated clientDirect, authenticated
Direct, anything else (unauthenticated API calls, back-office pages, the health probe, static files)Direct, other
Through the edge, an API call by an authenticated clientAuthenticated
Through the edge, an API call with no valid credentialAnonymous
Through the edge, anything elseNot recorded

Each kind and each platform has its own cap, sized to about a day of its expected volume, so a busy platform cannot push a quiet one out, an anonymous flood evicts only anonymous records, and a known client calling directly cannot push an unknown one out of Direct, other.

Who sees what

Every signed-in back-office account may open the page; nobody can change or clear it. A public source address is shown in full only to the auto-fix admins; everyone else sees its /24 (IPv4) or /48 (IPv6), so 203.0.113.9 reads 203.0.113.0/24. Private, tunnel, CGNAT, loopback and link-local addresses are shown in full to everyone. The masking happens before the page is built, so no link, tooltip or filter carries more than the viewer may see.

The direct-source summary

Beside the capped records, the dashboard keeps in memory every source that reached it directly since it started (up to 512): first seen, last seen, how many requests, the last route class and whether it ever authenticated. Caps and trimming never touch it, so a missed day still shows that an unknown peer called. The Unknown direct sources tile counts the ones that never authenticated. A dashboard restart empties it; the page says since when it holds.

What the page cannot see

  • Requests the proxy answers without the dashboard: anything outside /app/ and /api/ (the landing page and the docs), and the two slash redirects /app and /docs. The proxy’s own access log shows those.
  • A connection that never sends a complete HTTP request, such as a port scan.
  • Anything older than 48 hours, or pushed out by its kind’s cap: each kind shows how far back it reaches (“kept since”, marked cap when full).
  • Anything recorded before a restart of the traffic store or of the whole stack: nothing is written to disk, so a restart empties every stream. A dashboard redeploy alone keeps them, and empties only the summary.

Detection, not prevention

An empty direct list is not proof that no direct caller exists. Until the host firewall on the tunnel port is applied (recommended hardening, the edge runbook’s section 5), a direct peer can reach every route.

The daily review

Open Traffic at least once a day, and always before the shortest “kept since” of Direct, other runs out. Look at the direct-source summary first: every source there should be a known client (the QA tool’s backend, Jenkins, the VM itself). An unknown one is the finding. Then the platforms: failed calls, a platform that stopped answering, or a kind at its cap.
