Changelog

GAOS's single release history. Every user-visible change lands here, versioned with semantic versioning.

Versioning policy

Releases follow SemVer: MAJOR.MINOR.PATCH.

Major

Breaking changes: the graph schema, the event catalog, or a deployment needs attention to keep working.

Minor

New capability, backwards compatible — new views, endpoints, deployment targets.

Patch

Fixes and internal improvements. Nothing to change on your side.

Keeping it honest

The current version lives in assets/toc.js (product.semver) and is shown in the header badge. A release isn't done until this page and that field are updated — treat them as one change.

v0.10.0 2026-08-17 minor

The seam dashboard/store.go declared a pass ago is implemented, and store.go did not change to allow it. Dev and prod stop serving fixtures: a restart now rebuilds the floor from the graph.

  • Added dashboard/store_arcade.go — the ArcadeDB implementation of the Store seam, all twenty-four methods. The graph is authoritative and every mutation writes its events before it commits (BR-01, BR-02); reads are served from an in-memory projection rebuilt from the graph on boot, which is the cache BR-01 explicitly allows. Closes T-006.
  • Added a query path in dashboard/arcade.go — parameterised query, command and transaction against the ArcadeDB HTTP API, stdlib only, plus dashboard/schema_embed.go so the distroless binary applies its own DDL on boot instead of needing a shell. Closes T-007.
  • Added one conformance suite for both stores — dashboard/store_conformance_test.go, thirty-two cases that take a Store and nothing else, run against MemStore and against a live ArcadeDB. Plus deploy/schema/scratch.sh, which is the one command that produces the throwaway database the second half needs. Closes T-008.
  • Added D-047 — the data model gave an identity index to seven of its twenty-five vertex types, and 26.7.2 refuses a write keyed by business id against a type without one. Seven more were added; the DDL now applies 321 statements rather than 314, still idempotent. Found by writing to the graph rather than by reading the model, which is the same way D-046 was found.
  • Changed dev and prod run the graph store. Both compose files set GAOS_STORE: "arcadedb", and the binary refuses to start rather than falling back to fixtures — a dashboard that quietly served them would look completely healthy while losing every write. deploy/check-stacks.sh gained a check per tier so a silent revert cannot ship.
  • Changed The QA test plan register goes from one hundred and twelve cases to one hundred and thirty: TC-113…TC-130 cover the query path, the embedded schema, the conformance suite for both stores, the restart that proves the projection is reconstructible, and the two new deploy checks.

v0.9.0 2026-08-16 minor

The graph schema stops being a document and becomes a database. Ten runnable DDL files, applied against the pinned ArcadeDB version for the first time — which is how two errors in the committed data model were found.

  • Added dashboard/schema/ — the DDL from artifacts/v1/gaos-arcadedb-model.html extracted into ten numbered .sql files, and deploy/schema/apply.sh to apply them. 314 statements, applied clean against ArcadeDB 26.7.2 — the version D-043 pins — and idempotent, so a second run is a no-op. Until this ran, the schema existed only inside an HTML page and no DDL had ever met a database, which is what risk R-03 was about. Closes T-001…T-005.
  • Fixed D-045 — edge uniqueness is an index, not a keyword. ArcadeDB 26.7.2 rejects CREATE EDGE TYPE … UNIQUE outright, which failed all 32 edge types and, through them, the 18 property declarations naming a type that was therefore never created — 50 of the 53 statements that failed on the first run. The constraint is supported; only that spelling is not. It is now a unique index on (`@out`, `@in`), verified to refuse a duplicate edge between the same pair.
  • Removed D-046 — bucket-partitioning by tenantId is withdrawn. This one was an error in the data model rather than a dialect difference: partitioned(p) requires a unique index on exactly (p), so partitioning by tenantId requires tenantId to be unique — which permits one Task per tenant. Measured, not argued: a second Task for the same tenant failed with DuplicatedKeyException. tenantId stays indexed, so BR-26 is still met, and isolation rests where D-042 puts it — database-per-tenant.
  • Changed artifacts/v1/gaos-arcadedb-model.html amended in place at §04, §09 and §13, each with a visible callout naming the decision that changed it. The block that was wrong is left as first written with the correction above it, so a reader meets the amendment where they would otherwise copy the mistake. The document's own version-check warning — which told us to do exactly this — now records that it was done, and that it was worth doing.
  • Added Four schema guards in dashboard/schema_test.go, registered as TC-109…TC-112: the documented type counts, every edge type carrying its uniqueness index, every declaration carrying IF NOT EXISTS, and no gap in the numbered files. They need no database — they guard the reconciliations, which would otherwise rot silently, since duplicate edges do not raise, they accumulate. The register goes from one hundred and eight cases to one hundred and twelve.

v0.8.0 2026-08-15 minor

Six open questions answered in one block. What success means, what Mission Control is for, whether there is one model provider or several, how tenants are separated, which database version, and what the cost estimator does when it cannot price a model.

  • Added D-039 — answers OQ-08. Success is conformance, not a business number. GAOS is done when it builds and runs without issue and passes every acceptance criterion and every scenario in the QA test plan — positive and negative alike, all one hundred and eight cases — plus the three §4.1 acceptance tests. Numeric outcome targets stay unset until the second-run measurement has actually been performed once, because a percentage invented against no baseline measures whoever chose it.
  • Added D-040 — answers OQ-15. Mission Control is both: one role-gated surface for operators and internal operations, never a fork. The answer takes the bill the question attached to it — authentication, per-tenant scoping and accessibility become preconditions on further work here, which promotes OQ-11 from open question to blocking dependency. Recorded as I-8.
  • Added D-041 — answers OQ-09. Multi-provider behind the model gateway, with CLI mode the MVP's focus. Anthropic is the first adapter rather than the only one; the providers that ship first are those whose command-line tool clears OQ-23's contract, and API mode remains available for one whose CLI cannot be driven.
  • Added D-042 — answers OQ-10. All three tenancy strategies stay reachable behind one repository interface, and which one a deployment uses becomes configuration. Database per tenant remains the default; tenantId stays declared and indexed under every strategy. This narrows D-011 rather than reversing it, and pays for the interface up front instead of picking late.
  • Added D-043 — answers OQ-17. The target is ArcadeDB 26.7.2, the version already running, which clears the v26.5.1 floor EXTERNAL properties need. The DDL runs against a scratch database on that version before build-order step 1 writes anything, verifying L-7's independent payload deletion in the same pass.
  • Added D-044 — answers the first half of OQ-22. Token usage is estimated locally and priced from a configured table, and a model the table does not know produces no cost rather than a zero. Zero is the dangerous answer, because it is a figure the budget guard will let through. Where the price table lives and who maintains it is still open, so the question is narrowed rather than closed.
  • Added Two business rules. BR-36 — the escalation ladder is defined in normalised tiers, never vendor model names, because BR-15's "one tier above" has no cross-vendor meaning otherwise. BR-37 — a cost that cannot be priced is reported as unavailable, never as zero.
  • Changed The BRD moves to baseline 0.4. §1.4's "no measurable business targets exist" warning becomes a decided statement, BR-26 is amended to a configurable tenancy boundary, I-8 and a rewritten J-1 land, ArcadeDB is pinned in §5.3 and §10.3, R-03 and R-08 get mitigations that are decided rather than proposed, and three rows of the §16 matrix flip to decided with their rejected options kept intact.
  • Changed The QA test plan is now the project's definition of success rather than only its test register. No case was added, changed or removed — the count stands at one hundred and eight.

  • Changed CONTRIBUTING.md's "what belongs in this repository" section states the decided boundary instead of pointing at an open question.

Twenty-three positive, thirty-two negative.

v0.5.0 2026-08-08 minor

GAOS is licensed and can be published. Execution stops being CLI-or-API and becomes CLI-and-API behind one switch, and the budget cap gets the thing it was missing: a way to slow down instead of stopping dead.

  • Added LICENSE — Apache-2.0, plus NOTICE with the trademark reservation and third-party attributions, and CONTRIBUTING.md with a DCO sign-off, the open-core boundary rule, and the local checks that stand in for CI. Logged as D-035; closes OQ-20, the one item that blocked publishing the repository at all.
  • Added BRD §7.6.1–7.6.3 — the master configuration that selects the execution adapter, a ten-row CLI-versus-API comparison led by the cost consequence (flat subscription with imprecise accounting, or metered with exact accounting), and the containment for each CLI weakness. Requirements D-12 and D-13, and D-036.
  • Added BRD §8.10.1 — the budget guard: three zones, spend paced across the period, and deferral instead of failure at the throttle threshold, so work waits for budget rather than dying of it. Five new Tenant properties, requirements J-9…J-13, and D-037; answers OQ-18.
  • Changed The execution path is now dual-mode everywhere it appears — the flowchart, domain D, the third-party table, the constraints, the FAQ — with one prohibition holding it together: the mode may be recorded on an attempt and never branched on (BR-33). BR-34 keeps deferral out of the retry accounting; BR-35 states that a limit which only warns is not a limit.
  • Changed An idle desk now has five blocking reasons rather than four — budget deferral joins them, with the time it resumes, so a budget pause never reads as a hang (§7.4, I-7).
  • Fixed R-12 is no longer a single point of failure: an operator whose provider CLI cannot be driven safely now changes a setting instead of forking. R-05 keeps its severity — the guard is designed, not built.

v0.2.0 2026-08-08 minor

Gives the design a business layer. Nothing executable changed — this release is the document that the code implementation will be written against, plus the register of decisions it deliberately does not make.

  • Added BRD — Business requirements — the three documents in artifacts/v1/ restated as business requirements across eleven domains, with a 26-entry business rule register, a nine-entry risk register, a scope boundary, and a business decision matrix. Every claim points at an artifact section, a committed file, or git history; everything else is marked open rather than invented.
  • Added Open questions — eighteen decisions with their options and trade-offs: the commercial model, pricing basis, who pays the model provider, plan definitions, service level, data residency, tenancy strategy at scale, the authentication approach, the ArcadeDB target version, and the budget caps that are specified everywhere and implemented nowhere.
  • Added Decision log — twenty-four decisions already made and traceable, from the graph-is-the-primitive thesis through to the cookie rule behind the tunnel. It is where an answered open question lands.
  • Added A Product navigation group (assets/toc/product.js), placed before Architecture because the business layer reads first.

v0.1.0 2026-08-07 minor

Stands the product up as a deployable thing. The agent OS itself is design only — this release is the path from a browser to a running container, proved end to end.

  • Added Mission Control at /app/ — the prototype in artifacts/v1/gaos-mission-control.html ported to Go and HTMX. Stdlib only, no go.sum, templates and assets embedded, 33 tests. The floor, inspector, timeline, replay scrub, meeting overlay, back office and the create-workflow wizard all render server-side.
  • Added Architecture — the system (six layers, the control loops, scoring and guardrails, readiness bands, replay, build order) and the graph (25 vertex types, 32 edge types, the event document, the indexes and invariants).
  • Added Infrastructure — product slot 03, ports 18301 and 19301, both tiers behind the WireGuard tunnel with the edge config and its runbook committed under deploy/edge/.
  • Added deploy/check-stacks.sh, which asserts the two failures a running stack will never tell you about: a dev tier wired to the production database, and a proxy published on every interface instead of the tunnel.
  • Added This documentation site and a landing page, both vendored from a sibling repository. The docs engine underneath is Pustaka; its own authoring guides are kept under Maintaining these docs.
  • Note Not built yet, and each page says so: no DDL is applied and no graph query is issued — the dashboard reads fixtures behind an interface and probes ArcadeDB only for reachability; the floor is a simulation goroutine standing in for the scheduler and runner; and the back-office login checks nothing, exactly as the prototype did.

Version numbering starts here: this history tracks GAOS, not the docs engine it happens to run on.
