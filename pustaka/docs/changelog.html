Changelog

GAOS's single release history. Every user-visible change lands here, versioned with semantic versioning.

Versioning policy

Releases follow SemVer: MAJOR.MINOR.PATCH.

Major

Breaking changes: the graph schema, the event catalog, or a deployment needs attention to keep working.

Minor

New capability, backwards compatible — new views, endpoints, deployment targets.

Patch

Fixes and internal improvements. Nothing to change on your side.

Keeping it honest

The current version lives in assets/toc.js (product.semver) and is shown in the header badge. A release isn't done until this page and that field are updated — treat them as one change.

v0.25.0 2026-11-02 minor

A published Blueprint now reaches the product's workspace, and nothing is dispatched through the gateway under rules the workspace does not hold. M14.4.

  • Added one workspace per product. Sync to workspace on the Blueprint tab provisions gaos-<tenant>-<product> through ai-manager the first time and replaces its files after, guarded by the digest; a repeat is a no-op. The files pass the egress pass first, and a credential in a policy refuses the sync with DispatchRefused rule egress-blueprint before anything is written — which finishes T-154. WorkspaceProvisioned and BlueprintSynced join the catalog and the fold.
  • Added the drift gate and the pin (BR-39). Through the gateway, a product whose workspace does not hold its published Blueprint is refused as blueprint-drift on the scheduler's route and the operator's alike, and the next sync releases it. Every attempt records the version it ran under (PINNED_TO), its request id and its session id.
  • Changed one live turn per product (BR-38). The scheduler now treats a DISPATCHED or RUNNING task as holding its product, folder or no folder. Two workspaces of one product no longer license two runs, and TC-218's second half moved to two products.
  • Fixed a data race in ai-cli-common (ardi-personal-workspace-ai PR #323, deployed): CreateFromSpec handed its caller the job a worker was already writing, which the POST /v1/jobs handler read for its 202; and test managers that never drained their workers.
  • Fixed the handoff artifact constraint is live on dev — schema: 365 statements from the embedded DDL, none failed (169 accepted, 196 already declared). It was latent rather than active there: dev runs no adapter, so nothing had tried to store a handoff yet.

v0.20.0 2026-08-22 minor

Build-order step 5 passes: kill the orchestrator mid-task, and the work survives and is re-adopted. M4.2 closes, the closed catalog's execution group is fully emitted for the first time, and the recovery pseudocode in the architecture document turns out to have been wrong about the one branch that matters.

  • Added boot reconciliation (T-053). dashboard/reconcile.go holds the decision as a pure function and runner.go the pass that acts on it. It runs before the listener, because a request served first would see a floor lying about what is in flight, and a failure fails the boot — a dashboard that could not work out what was running, then served a floor as if nothing were, looks completely healthy while a detached process edits a repository nobody is watching.
  • Fixed the architecture document's recovery branch, and the event it named (D-054). The middle branch was commented "lease held, process gone". It does not know the process is gone. It knows the beat is stale, and a stale beat means the SUPERVISOR died — which says nothing about the child, because D-2 detached it precisely so it would outlive its supervisor. Requeuing on that basis starts a second run in a workspace that may still have a live one in it: the corruption D-3 exists to prevent, reached through the recovery routine. So requeue kills first, and where nothing is able to kill it degrades to an orphan rather than requeuing on a promise it cannot keep. The page also emitted TaskFailed, which is not in the closed catalog at all.
  • Added Stop on the adapter seam. The reconciler has to be able to say “make this dead”, and what that MEANS is mode-specific — a signal to a process group for a CLI run, cancelling a request for the API adapter. A reconciler that knew about pids would be one that only worked for one mode, which is what BR-33 forbids.
  • Added the control loop, and a flush hook the runner needed to exist at all. One pass asks the scheduler what may start and starts it. Along the way: the runner is the first writer in this codebase that is nobody's request, so there is no mutate() around it and its events would have lived and died in the projection. MemStore.onWrite is how a background writer reaches durable storage. The first version deadlocked the boot — the reconciler held the store lock while the hook tried to take it — and the acceptance test below is what found it.
  • Added deploy/acceptance/kill-mid-task.sh (TC-243…TC-246). This cannot be a Go test, and pretending otherwise would be worse than not having it: the property is that a child outlives its parent, and under go test the test binary is that parent while the harness reaps the tree on exit. Two limits are printed rather than discovered — it never runs against dev or prod, and it cannot run with GAOS_STORE=memory, because a memory store loses every task record on restart and would pass by having nothing to check.
  • Changed TaskOrphaned came off the owed list, and with it the whole execution group. The split is worth keeping in mind: the three names that landed one release ago are exactly the ones a live supervisor can witness, and this one needed the only thing that can observe an orphan — a restart. No supervisor ever sees one, because an orphan is a run whose supervisor is already gone.
  • Note a finding the acceptance test surfaced and this release does not fix. CreateWorkflow seats an agent on the desk, and the scheduler then sees that agent as busy for the plan's first task — the same work, double-booked. The scheduler is right to refuse and says why; the desk-level seating predates a scheduler that seats per task. It wants its own change rather than a quiet one here.

v0.19.0 2026-08-22 minor

A real tool now runs, supervised, against a leased workspace — and it outlives the process that started it. Three names come off the closed catalog's owed list, which is the first time that has happened since the list was written.

  • Fixed D-2 was false on the path an operator actually uses. Dispatch built its context from the caller's, and serve() builds the caller's from signal.NotifyContext(SIGINT, SIGTERM) — so a graceful shutdown cancelled the context and CommandContext killed the child, while SIGKILL left it running because the Go runtime never gets to act. The ungraceful path satisfied D-2 by accident and the graceful one violated it on purpose. context.WithoutCancel is the fix; the only cancellation left is the run's own twenty-minute timeout, which is a property of the run rather than of its supervisor.
  • Added the supervisor (T-050, T-052). dashboard/runner.go takes the lease, writes the run record, hands the cleared packet to the adapter, beats while the work runs, and records what came back. The heartbeat attests to the supervisor, not to the model — Claude Code knows nothing about GAOS — so when an orchestrator dies the beat goes stale while the work continues. That asymmetry is easy to read backwards, and reading it backwards is how a recovery routine requeues a task whose child is still editing the repository. It is why D-4 has three branches rather than two.
  • Changed the run's output goes to files, and that is what makes adoption complete rather than partial. The tool's JSON envelope carries total_cost_usd. In a bytes.Buffer it lives in the orchestrator's address space, so a process adopting the run could recover the outcome from the handoff and never the cost — which D-051 requires as measured from the first run. On disk, one collect() runs on both paths, and an adopted attempt is byte-identical to a supervised one.
  • Added Resume on the adapter seam, and a RUN.json for it to read. An adopting orchestrator cannot cmd.Wait() on a process it did not fork, so adoption needs its own entry point. Dispatch's signature is untouched, so BR-32 still holds; the pid, process group and process start time ride in an opaque Detail map that nothing above the adapter reads, which is what keeps BR-33 true when the HTTP adapter arrives. The start time is there because PID reuse is real and a bare probe after a reboot finds a stranger's process.
  • Fixed the handoff document is emptied before an invocation, which handoff.go has claimed since it was written and nothing did. Without it a retry in a reused workspace reads the previous attempt's document — and the direction of that mistake is the worst available, because a run that produced nothing looks like one that succeeded.
  • Added six guards in front of a paid model call, four of which already existed. New: GAOS_RUNNER, off by default and deliberately separate from whether an adapter is configured — an operator who set GAOS_MODEL_MODE=cli to make the boot smoke test run has not thereby authorised spending — and a refusal to exec anything outside testdata from a test binary. The honest caveat: the version pin is not a guard. The fake answers --version with exactly 2.1.238 (Claude Code), so the smoke test passes identically against both. The pin protects against drift, not against spend.
  • Changed RunStarted, Heartbeat and RunExited came off the owed list in dashboard/events.go, with their reducer cases, per BR-05. TaskOrphaned did not, and the split is worth noticing: the three that landed are exactly the ones a live supervisor can witness, and the one still owed is the one only a restart can observe.

v0.18.0 2026-08-22 minor

The lease, which the rest of M4.2 is unsafe without. Small, and it carries the one decision in this pass that reads like a bug until you know why it is not: an expired lease is still refused.

  • Added the exclusive workspace lease (T-051). dashboard/lease.go — an O_EXCL lockfile at .gaos/run/LEASE.json, with acquire, renew, release and break. D-3 names the failure it is written against and it is not a loud one: "two runs in one workspace corrupt each other silently" — two agents editing one checkout do not crash, they produce a diff neither of them wrote, which is then reviewed, scored and possibly merged. A lockfile rather than a row, because the thing being protected is a directory and the only primitive that excludes atomically at that granularity between processes is the filesystem. The record stays in the graph; BR-01 is intact because this is state on the resource rather than state in the process.
  • Added D-053: an expired lease is never taken by the acquirer, and the two heartbeat cadences are different numbers. The first reads like an oversight — the expiry passed, so surely the next runner may have it — but an expiry says the supervisor stopped renewing, and D-2 detaches the child precisely so it outlives its supervisor. Taking it starts the second run. Clearing one is BreakLease, a separate name for an operation only safe once the previous run has been made dead. The second: the beat is a field write every 30s, the Heartbeat event is written every 300s. At 30s a twenty-minute run puts forty pills into a stream that is append-only, snapshotted every 500 events and rendered in full; at 300s it puts five, and a replay can still tell alive at T from silent since T.
  • Note an unreadable lease counts as held. Treating a truncated lockfile as “no lease” would hand the workspace to a second run on the strength of a half-finished write — the exact failure the file exists to prevent, reached through the mechanism meant to prevent it. Renewal is write-then-rename for the same reason, so a reader sees the old lease or the new one and never half of either.
  • Fixed two counts that had drifted before this release. The decision log said fifty-two entries and the BRD's pointer to it said fifty-one; there are fifty-three now and both say so.
