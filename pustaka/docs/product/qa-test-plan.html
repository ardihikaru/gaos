QA test plan

Answers OQ-13 — who runs the acceptance tests and how often — and enumerates every test scenario that follows from it: two hundred and nineteen cases, positive and negative, across the three deploy automations and the two Go test packages that actually run today, plus the two business acceptance tests BRD §4.1 specifies and nothing has yet executed — the third, the fold test, runs as of v0.11.0 and has moved into the register proper. Since D-039 this register is also the project's definition of success: GAOS is done when every case here passes, positive and negative alike, and no numeric outcome target stands beside it.

How to read this register

Every row is a TC-nnn. Kind is Positive (the invariant holds, or the action succeeds) or Negative (the invariant is violated, or the action is refused) — both are listed for almost every scenario, because a check that never fails is unverified, not passing. Status is Implemented (the automation exists and this page describes its real, current behaviour, re-read from deploy/check-stacks.sh and deploy/rebuild-restart.sh at the time this page was written), Not implemented (a forward specification for a test the design commits to but nothing in the repository can run yet), or Retired (a case whose premise a later rule overturned — struck, never deleted and never renumbered, with the reason and the replacement on the row, because an ID that silently disappears is an ID somebody will reuse).

Who runs these tests, and how often

GAOS has no CI configuration anywhere in the repository — these automations only run when a human or agent invokes them by hand. BRD §5.1 names four internal roles — product owner, platform operator, fleet operator, record author — and notes they are currently one person. That person is the runner for everything below, whether they invoke deploy/rebuild-restart.sh directly or through the gaos-deploy subagent, which exists precisely so the same deterministic script runs the same way every time instead of a free-handed docker compose command drifting between invocations.
