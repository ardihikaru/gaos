Decision log

Every business and design decision GAOS has actually made, with the evidence that proves it was made. Twenty-five entries, each traceable to an artifact section, a committed file, or git history — and a destination for every question the open register resolves.

How this log works

A decision belongs here when it constrains future work and reversing it would cost something. It does not belong here because it seemed important at the time. Every row carries evidence: if a decision cannot be pointed at, it has not been made — it is an open question that somebody has been acting on informally.

The lifecycle

An entry on the open questions page is answered by the product owner. The answer is written here as the next D- number, dated the day it was decided, with the reasoning in the decision text and the evidence pointing at whatever records it. The question's row then flips to Answered → D-nnn. Nothing is deleted from either page; a reversed decision is superseded in place, the way D-004 would be if the event id scheme ever changed.

Dates appear only where git history or a document supplies one. A dash means the decision is embedded in the design artifacts committed on 2026-08-02 without a separately recorded date — which is honest, and better than inventing a day.

Data model

IDDateDecisionEvidence
D-0062026-08-02 One edge type per relationship, never a generic edge with a type property. Traversal by edge type is index-free adjacency; filtering a generic edge by property scans every neighbour. Named in the source document as the single biggest performance decision in the model. gaos-arcadedb-model.html §01 principle 3
D-0072026-08-02 Task and TaskRun are separate types. Folding attempts into the task would destroy the cost, model, failure signature and logs of every previous attempt, making the retry loop untunable and model comparison in replay impossible. gaos-arcadedb-model.html §03
D-0082026-08-02 USES_CONTEXT hangs off ContextSlice rather than Task, because the slice differs per attempt — that is the whole point of retrying with a widened context. gaos-arcadedb-model.html §04
D-0092026-08-02 Schema-full where machines read, schema-less where humans write: Task, Event and Review are strictly declared because the scheduler and the fold depend on their shape, while Requirement and Artifact carry a declared spine plus free-form fields. gaos-arcadedb-model.html §01 principle 1
D-0102026-08-02 Heavy payloads — prompt bodies, rendered slices, diffs, log blobs — are marked EXTERNAL or kept as references to object storage, because inline properties are serialized on the same page as the vertex topology and cost cache misses on every traversal that never projects them. gaos-arcadedb-model.html §01 principle 5, §13
D-0112026-08-02 Tenancy is a database boundary first and a property second. One database per tenant is the default recommendation; tenantId is declared and indexed on every vertex regardless, because it survives exports and makes a misrouted restore detectable. gaos-arcadedb-model.html §01 principle 6, §13
D-0122026-08-02 Retention differs by type: events at full fidelity for 90 days then archived with the fold checkpoint retained, samples raw for 14 days then downsampled, run logs by reference only, and everything else indefinitely — because the audit trail is the product. gaos-arcadedb-model.html §13

Control-loop policy

IDDateDecisionEvidence
D-0132026-08-02 Readiness is scored out of 100 against twelve machine-checkable signals, and the planner refuses to plan below 45, returning the list of what is missing. A subjective bar would get argued away; a published rubric cannot be. gaos-architecture.html §07
D-0142026-08-02 Readiness decays rather than persisting: effective = raw − drift_penalty, penalty capped at 25, and crossing a band boundary downward emits an event and applies the stricter gates immediately instead of recalculating silently. gaos-architecture.html §07
D-0152026-08-02 Role and model selection is ordered capability → risk → cost, never cost first — selecting on cost first routes a security-critical migration to the cheapest model because it happened to be free. gaos-architecture.html §05
D-0162026-08-02 Correctness is weighted 0.45 of the final score, dominating the other four dimensions deliberately: a beautiful implementation of the wrong behaviour should score below an ugly implementation of the right one, because the second is cheap to improve and the first is expensive to discover. gaos-architecture.html §06
D-0172026-08-02 Safety is a veto, not a weight: below 60 the work stops regardless of the total, emits SafetyVeto, and goes to a human queue. And an identical failure signature twice routes to a design review rather than a tier escalation, because escalating usually reproduces the same wrong answer more expensively. gaos-architecture.html §06
D-0182026-08-02 Build order is prescribed in ten steps, with Mission Control at step 9 and an explicit warning against starting with the visual layer because it is the most rewarding to build and the least load-bearing. gaos-architecture.html §10

Quality assurance

IDDateDecisionEvidence
D-0252026-08-08 Answers OQ-13. Since GAOS has no CI and its four internal stakeholder roles are currently one person, that person is the runner for every acceptance test, whether invoked directly or through the gaos-deploy subagent. check-stacks.sh and the post-deploy verification in rebuild-restart.sh run automatically on every deploy and restart, both tiers, and refuse the action on failure; the test/check gate runs automatically on every deploy only. The three BRD acceptance tests have no automated cadence yet because nothing exists to run them against — proposed cadence is before every release (unsatisfiable task), weekly once a scheduler exists (fold test), and on demand with at least one run to seed the OQ-08 baseline (second run). Fold-test divergence and unsatisfiable-task guard-limit failures are release blockers, not warnings; the second-run result is a viability signal that triggers a review, not an automatic gate. product/qa-test-plan.html; deploy/check-stacks.sh; deploy/rebuild-restart.sh
