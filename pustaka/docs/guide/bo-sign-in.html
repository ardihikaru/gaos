Back-office sign-in

The back office is the part of GAOS that writes: products, requirements, Blueprints, answers and the QA sync buttons. It signs an operator in with an email and a password checked against a hashed file, and every route that is not public is refused without a valid session. Built in v0.39.0 (D-079).

What it is

An account is one line of a text file. A session is a signed cookie that lasts twelve hours from sign-in and is checked on every request. There is no open mode: with no account configured, nobody can sign in, and in production the deployment label must be set too (BR-55).

Accounts

The server reads GAOS_BO_USERS_FILE once at start. Each line is email:pbkdf2-sha256$600000$<salt>$<hash>; blank lines and lines starting with # are ignored, and a bad line is skipped and reported by its number, never its content. To make a hash, give the password on standard input; it is never an argument, so it does not appear in a process list:

sh
docker run --rm -i --entrypoint /dashboard <IMAGE> hash-password < password-file

Add the printed line to the users file and restart the dashboard. The file and the session key are secrets: mode 0600, never committed (deploy/stacks/prod.bo-users and prod.bo-session-key are gitignored), and the dashboard warns at start when either is readable by others.

Sessions and revocation

The cookie is v1.<email>.<expiry>.<fingerprint>.<mac>, signed with HMAC-SHA256 under GAOS_BO_SESSION_KEY_FILE (raw bytes, at least 32) and the deployment label GAOS_BO_LABEL, so a cookie from one deployment is worthless on another. Sessions are stateless, so they end in these ways only:

  • twelve hours after sign-in (no sliding renewal);
  • when the account's password changes or the account is removed, once the dashboard restarts with the edited file (the fingerprint is part of the signature);
  • when the key changes or, with no key file, when the dashboard restarts.

Signing out clears the browser's cookie but cannot recall a copy somebody stole; the twelve-hour bound and the steps above are what limit it. An open event stream closes when its session expires.

Throttle

Five wrong passwords for one account within fifteen minutes lock that account for fifteen minutes. A locked account answers “Too many attempts” with a Retry-After and does not check the password. Made-up emails never lock and answer the same text as a wrong password. There is no per-address lock on purpose: behind the proxy every client shares one address, so it would let anyone lock everyone out.

A non-GET request that a browser marks cross-site, or whose Origin names another host, is refused with 403, sign-in and sign-out included. Replay is a POST now.

What this does not do

All accounts are equal; there are no roles and no per-tenant scoping. Events record no actor, so the log cannot yet say which operator cleared a Blocker. There is no password-reset page: an operator with shell access edits the file. Pages on the same origin as the dashboard (the docs) can still make requests as a signed-in operator; no check stops a docs page from loading a third-party script yet.
